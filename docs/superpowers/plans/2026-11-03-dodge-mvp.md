# Dodge MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Dodge MVP: solo, LAN party and private online party play of a 2D hazard-dodging arcade game, from one authoritative server codebase.

**Architecture:** `shared/` holds the pure simulation, validation and wire protocol with no graphics. `server/` holds pure party/lobby logic plus an ENet host loop, built as a library and a headless exe. `client/` is a raylib/raygui app that runs the server library on a background thread for solo and LAN, or connects to a remote server for online.

**Tech Stack:** C++20, CMake >= 3.24 with `FetchContent`, raylib 5.5, raygui 4.0, ENet 1.3.18 (lsalzman/enet), doctest 2.4.11.

**Spec:** `CLAUDE.md` (project root). Read it before any task.

## Global Constraints

- `shared/` and `server/` must not include raylib or any Windows-only header. They must build on Linux.
- Server is authoritative. Every byte received from a client is untrusted: decode with bounds checks, drop malformed packets, never crash.
- Arena: 1280x720 logical units. Max 4 players per party.
- Lobby countdown 3 s. Results countdown 5 s. Solo countdown 3 s.
- Names: 1 to 12 ASCII chars from letters, digits, space, `_`, `-`; trim surrounding spaces; reject empty.
- Party code: 5 chars from `ABCDEFGHJKMNPQRSTUVWXYZ23456789`, case-insensitive, unique among live parties.
- Protocol version `1`. Game port UDP `7777`. LAN discovery port UDP `7778`.
- Server simulation 60 Hz. Snapshots 30 Hz.
- Starting tunables (in `shared/constants.h`, adjust by playtest): player radius 16, player speed 300 u/s, hazard radius 12, hazard speed 250 u/s, spawn interval `max(0.15, 1.0 - 0.01 * t)` seconds.
- The project folder is not yet a git repo. Task 1 runs `git init`.

## Review Focus

1. Malformed, truncated or oversized packets from a client must be dropped without a crash or state change. Test in Task 5.
2. A player disconnecting during the lobby countdown must cancel it if the party drops below 2. Test in Task 6.
3. The last two players eliminated in the same tick must share a placement (both 1st). Test in Task 4.
4. A client sending input outside -1..1 (cheating or bug) must be clamped by the server, never move faster. Test in Task 3.
5. Non-ASCII or 13+ char names must be rejected by the server even if the client let them through. Test in Task 2.

### Task 3: Simulation, players

**Files:** Create `shared/sim.h`, `shared/sim.cpp`, `tests/test_sim_players.cpp`

**Interfaces:**
- Produces:
```cpp
struct Vec2 { float x = 0, y = 0; };
struct Input { float dx = 0, dy = 0; };            // client intent, clamped by server
struct PlayerState { uint8_t id; Vec2 pos; bool alive = true; float survived = 0; uint32_t outTick = 0; };
struct Hazard { uint32_t id; Vec2 pos; Vec2 vel; };
struct World {
  uint32_t tick = 0; float time = 0; float spawnTimer = 0; uint32_t nextHazardId = 0;
  std::vector<PlayerState> players; std::vector<Hazard> hazards; std::mt19937 rng;
};
```

- Players start in a 2x2 grid centered on the arena, 60 units apart, in `playerIds` order.

Eliminated players record `survived = w.time` and `outTick = w.tick` and stop moving. Living players accumulate `survived`. (Hazard spawning is Task 4; for now `stepWorld` spawns none.)

  - `"leaving arena eliminates"`: player at `{5, 360}`, input `{-1,0}`, step 0.1 s; `alive == false`, `allEliminated(w)`.
  - `"dead players do not move"`: after elimination, further steps leave `pos` unchanged.

### Task 4: Simulation, hazards, difficulty, placements

**Files:** Modify `shared/sim.h`, `shared/sim.cpp`. Create `tests/test_sim_hazards.cpp`

**Interfaces:**
- Consumes: Task 3 types.
- Produces:
```cpp
float spawnInterval(float t);                      // max(0.15, 1.0 - 0.01 t)
Hazard spawnHazard(std::mt19937& rng, uint32_t id);
struct Placement { uint8_t id; uint8_t place; float survived; };
std::vector<Placement> placements(const World& w); // sorted by place
```
- `spawnHazard`: pick edge 0..3 uniformly, pick a uniform point along it, start `kHazardRadius` outside that edge, velocity perpendicular inward at `kHazardSpeed`.
- `stepWorld` now: decrement `spawnTimer`; when <= 0 spawn one hazard and add `spawnInterval(w.time)`. Move hazards. Remove a hazard once its center is more than `kHazardRadius` beyond any arena edge. Eliminate living players whose distance to any hazard < `kPlayerRadius + kHazardRadius`.
- `placements`: later `outTick` places higher; equal `outTick` share the same place (standard competition ranking: two tied at top are both 1, next is 3).

  - `"same-tick eliminations share placement"`: 3 players; A out at tick 10; B and C out at tick 20; `placements` gives B=1, C=1, A=3.

### Task 5: Wire protocol

**Files:** Create `shared/protocol.h`, `shared/protocol.cpp`, `tests/test_protocol.cpp`

**Interfaces:**
- Consumes: `Vec2`, `Input`, `Placement` from Task 3-4.
- Produces:
```cpp
enum class Mode : uint8_t { Solo, Lan, Online };
enum class RejectReason : uint8_t { Version, BadName, Full, Started, NoSuchParty };
struct LobbyPlayer { uint8_t id; uint8_t color; std::string name; bool ready; };
// client -> server
struct Hello { uint16_t version; Mode mode; std::string name; };
struct CreateParty {};
struct JoinParty { std::string code; };          // empty for LAN/solo
struct SetReady { bool ready; };
struct InputMsg { Input input; };
struct Leave {};
// server -> client
struct Welcome { uint8_t yourId; };
struct Reject { RejectReason reason; };
struct LobbyState { std::string code; std::vector<LobbyPlayer> players; float countdown; }; // countdown < 0 when not running
struct MatchStart { float countdown; };
struct Snapshot { uint32_t tick; std::vector<PlayerState> players; std::vector<Hazard> hazards; };
struct MatchEnd { std::vector<Placement> results; float countdown; };
struct PartyClosed {};
using Message = std::variant<Hello, CreateParty, JoinParty, SetReady, InputMsg, Leave,
  Welcome, Reject, LobbyState, MatchStart, Snapshot, MatchEnd, PartyClosed>;
std::vector<uint8_t> encode(const Message&);
std::optional<Message> decode(std::span<const uint8_t>);
```
- Format: 1-byte type tag = variant index, then fields little-endian; strings as `uint8_t` length + bytes; vectors as `uint16_t` count. `decode` returns `nullopt` on unknown tag, any read past the end, trailing bytes, string length > 64, or vector count > 512.

  - `"rejects huge counts"`: a `Snapshot` header claiming 60000 hazards with no payload decodes to `nullopt` without allocating.

### Task 6: Party logic

**Files:** Create `server/party.h`, `server/party.cpp`, `tests/test_party.cpp`

**Interfaces:**
- Consumes: `sanitizeName`, `World`/`stepWorld`/`placements`, protocol structs.
- Produces:
```cpp
using PeerId = uint32_t;
enum class Phase { Lobby, Countdown, Match, Results, Closed };
enum class JoinResult { Ok, Full, Started, BadName };
class Party {
 public:
  Party(Mode mode, uint32_t seed);
  JoinResult join(PeerId peer, std::string_view rawName);   // solo ignores name
  void leave(PeerId peer);
  void setReady(PeerId peer, bool ready);
  void setInput(PeerId peer, Input in);
  void tick(float dt);
  Phase phase() const;
  float countdown() const;                                  // -1 when none
  std::vector<LobbyPlayer> lobbyPlayers() const;
  const World* world() const;                               // null outside Match
  std::vector<Placement> results() const;
  std::optional<uint8_t> playerId(PeerId) const;
  bool empty() const;
};
```
- Rules (all from CLAUDE.md):
  - Join rejected `Full` at 4, `Started` outside `Lobby`/`Countdown`, `BadName` if `sanitizeName` fails (non-solo).
  - Color = lowest free index 0..3. The first joiner on LAN is the creator.
  - Solo: on join go straight to `Countdown` (`kSoloCountdown`), no ready.
  - Lan/Online: `Countdown` (`kLobbyCountdown`) starts when >= 2 players and all ready. Cancel back to `Lobby` on un-ready, new join, or drop below 2.
  - Countdown reaching 0 creates the `World` (`makeWorld`) and enters `Match`.
  - `Match`: `tick` steps the world with latest inputs. A peer leaving counts as eliminated now. When `allEliminated`, enter `Results` with `kResultsCountdown`.
  - `Results` reaching 0, or LAN creator leaving in any phase: `Closed`.
  - Online: party is `Closed` when `empty()`.

### Task 8: Server network loop

**Files:** Create `server/server.h`, `server/server.cpp`, `tests/test_server.cpp`. Modify `server/main.cpp`.

**Interfaces:**
- Consumes: `Party`, `PartyRegistry`, `encode`/`decode`.
- Produces:
```cpp
struct ServerConfig { Mode mode; uint16_t port = kGamePort; std::string lanName; };
void runServer(const ServerConfig& cfg, std::atomic<bool>& stop);   // blocks until stop
```
- ENet host, 2 channels: 0 reliable (lobby/control), 1 unsequenced (`InputMsg`, `Snapshot`). Fixed 60 Hz tick loop with `enet_host_service` timeout to the next tick.
- First message from a peer must be `Hello`; wrong version gets `Reject{Version}` and disconnect. Online peers then send `CreateParty` or `JoinParty{code}`; Lan/Solo peers join the single party directly.
- Send `LobbyState` reliably to all party members whenever it changes, `MatchStart` on entering `Match`, `Snapshot` at 30 Hz during `Match` and `Results` (spectators keep receiving), `MatchEnd` on entering `Results`, `PartyClosed` on `Closed`.
- Undecodable packets are dropped. A peer whose messages don't match its phase is ignored for that message.
- In Lan/Solo mode the loop exits when the party closes.
- `server/main.cpp`: parse `--port N`, run Online mode until SIGINT/SIGTERM.
